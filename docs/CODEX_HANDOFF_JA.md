# Codex引継ぎ — 写真で補修部品相談／ホシ姫サマ実証

## プロジェクトの核

依頼者に図面・材質・公差・部品名を要求せず、**写真4枚と簡単な言葉だけ**で補修部品相談を始められるようにする。

最初の実証対象は、ユーザー自身が修理を進めている「ホシ姫サマ」の樹脂部品。ここで受付、採寸案内、設計、試作、製造カルテ、再注文までを一巡させる。

## ユーザーが解決したい問題

- 製造業へ頼もうとしても、頼み方が難しく断念した経験がある
- 同じ製品の同じ部品で、他の人も困っている可能性が高い
- メーカー供給終了品を、設計データ在庫＋受注生産で届けたい
- 将来は注文通知から承認済み3MFの準備まで自動化したい
- 外部送信、購入、印刷開始などの重要操作は、当面GO確認を残す

## 現在できているもの

ルート直下の静的Web MVP。

- `index.html` — スマートフォン向け3ステップ受付
- `styles.css` — モバイル優先UI
- `app.js` — 写真プレビュー、入力保存、安全判定、相談整理票、コピー、メール下書き、JSON保存
- `.github/workflows/pages.yml` — GitHub Pages配備

### 現在の安全境界

- 写真も入力内容もサーバー送信しない
- 写真はブラウザー内プレビューのみ
- テキスト入力はlocalStorageのみ
- メールは宛先なしの下書きを開くだけ
- 注文、決済、CAD生成、印刷開始は未実装

## 次の実装順序

### Phase 1 — 実際に受付できる小さなバックエンド

1. ケースIDをサーバー側で採番
2. 写真を安全にアップロード
3. 入力内容をケース単位で保存
4. 管理画面でケース一覧・詳細を確認
5. 受付完了メールは自動送信せず、下書きまたは明示承認後に送信

推奨構成は、依存を増やしすぎない小さなNext.jsまたはFastAPI。最初は1人運用でよい。

### Phase 2 — AIによる不足情報整理

1. 写真と回答を読み、部品候補・故障様式・危険度を整理
2. 不足している寸法だけを抽出
3. 元写真に矢印・A/B/C記号を付けた採寸指示画像を生成
4. 依頼者へは「Aの端から端を測ってください」のように返す
5. AI判定は確定扱いせず、管理者レビューを必須にする

### Phase 3 — CAD・試作カルテ

1. ケースから設計タスクを作成
2. STEP/STL/3MFと設計根拠を版管理
3. 材料、ノズル、積層方向、外周、インフィルをカルテ化
4. 試作ごとの寸法差、嵌合、破損、修正量を記録
5. 販売承認された版だけ商品マスターへ昇格

### Phase 4 — 受注生産

1. 商品番号と承認済み3MFを紐付け
2. Yahoo!オークション、eBay、自社EC等の注文を受け取る
3. 注文内容から製造指示を自動準備
4. iPhone/Apple Watchへ「品番・材料・数量・時間」を通知
5. GOで印刷開始。完成品の取外しと検品は人が担当

### Phase 5 — 半自動製造

同一品番で十分な実績を積んだ後だけ対象にする。

- ビルドプレートが空であることを確認
- 材料・ノズル・残量・版数を照合
- 印刷中の異常監視
- 印刷完了後は自動発送に進まず、人の検品を残す

## 最初の受入条件

ホシ姫サマ1案件で、次を満たす。

- iPhoneから写真4枚と相談内容を登録できる
- 管理側でケースを開ける
- 不足寸法を最大5項目に絞って返せる
- 設計ファイルを版管理できる
- PLA試作→本番材料の結果を記録できる
- 完成部品にケースID・版数を紐付けられる
- 販売可否と自動印刷可否を別々に管理できる

## 販売対象の境界

初期販売候補：カバー、ノブ、キャップ、ガイド、スペーサー、収納・固定補助など低危険部品。

初期は販売しない：制動、操舵、座席固定、頭上重量物を直接支える部品、100V以上の充電・発熱部、転落や挟まれにつながる部品。

## 実装時の原則

- 依頼者へ専門用語を要求しない
- AIが分からないものを断定しない
- 版数・材料ロット・試験結果を消さない
- 外部送信・注文・印刷開始は明確な承認境界を持つ
- UIは「次に何をすればよいか」が一画面で分かること
- 将来の多機能化より、ホシ姫サマ1件を最後まで通すことを優先する
